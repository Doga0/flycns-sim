# v0.8 proposal: physical sensory-motor validation (LF tibia)

Status: **proposal, waiting for the owner's decision** (2026-10-12). Nothing here is
implemented. Evidence: [lf-tibia-pathway-report.md](lf-tibia-pathway-report.md).

## Why this direction

The v0.7.x investigation showed that the chordotonal → LF tibia pathway activates under the
current graph and LIF model with no weight or sign change. It needs sustained sensory drive
of about 87 Hz per cell, and it excites flexors 807165 and 809912 while inhibiting both
extensors. v0.7 failed because its protocol (+0.20 rad, then release) produced only a few
milliseconds of about 57 Hz before the actuator pulled the joint back.

The existing v1 encoder already reaches 100 Hz nominal at neutral + 0.35 rad. So the first
thing to change is the **experimental protocol**, not the network or the encoder: keep the
joint displaced long enough for the sensory population to drive the motor neurons.

## Step 0 (v0.7.x, done 2026-10-12): robustness of the activation threshold

Seeds 42–46, 50–200 Hz, 500 ms drive (results in [pathway-audit.md](pathway-audit.md#robustness-sweep-2026-10-12-outputsanalysislf_tibia_sweep_robustnessseed4246)):
- The threshold is soft. 50–90 Hz gives only sporadic motor spikes; 100 Hz gives 5–14 spikes
  per 550 ms with first spikes 51–208 ms after onset; 200 Hz gives 25–38 spikes within
  22–39 ms, in every seed.
- In all 35 driven runs only flexors 807165 and 809912 fire; the extensors stay silent.

Consequence for the protocol: the v1 encoder tops out at 100 Hz nominal (neutral + 0.35 rad),
so even a fully held displacement gives only the slow, sparse 100 Hz regime. Two options:
- **(a) keep the v1 encoder** and hold the load long (at least 500 ms near +0.35 rad).
  Expect a small, late effect. A rough estimate: about 10 motor spikes over 5 flexors in
  0.5 s gives a population rate of about 4 Hz and an activation of about 0.04, so a target shift
  of about 0.014 rad. That is close to the proposed 0.01 rad pass threshold (inference, untested).
- **(b) add a `sensory_lf_tibia_v2` encoder profile** whose maximum rate is about 200 Hz
  (same cells, same linear shape). Expect a clear effect within tens of ms. This is a
  new engineering assumption and needs the owner's approval.

Recommended order: run (a) first, since it changes nothing but the protocol. Consider (b)
only if (a) fails the gate.

## Step 1: sustained-load protocol (new closed-loop profile v2)

Add a new profile `configs/closed_loop/lf_tibia_v2.yaml`; `lf_tibia_v1.yaml` and its results
stay unchanged. It reuses the v0.7 scheduler, encoder (`sensory-bridge-v1`), decoder
(`motor-bridge-v1`) and LIF (`shiu-lif-v1`). The only new element is a **deterministic
external load** on the LF tibia joint, for example a MuJoCo `qfrc_applied` torque ramp held
for several hundred ms. The load is a function of time only, identical in all conditions,
and never depends on neural state.

Prediction from the current conventions: a positive displacement drives the
positive-position sensory channel, which activates flexors. The decoder then moves the
target in the negative direction, against the load, which acts like a resistance reflex.
The direction comes from the decoder convention (`extensor_direction: +1`, DECISIONS.md D7)
and is not a biological claim. It is recorded, not required.

Choose the load size from the open-loop step below so that the joint stays near
+0.25 to +0.35 rad, where the v1 encoder gives about 70–100 Hz nominal.

## Step 2: tests

**A. Unit and regression (no real data):**
- The load is deterministic, a function of time only, and bounded by the safety guards.
  It is applied identically in feedback_off, sensory_clamp and feedback_on.
- The v1 profile reproduces the recorded v0.7 result exactly:
  `closed_loop.validate <new run> --compare outputs/closed_loop/lf_tibia_seed42`.
- All existing tests pass, including the synthetic 3-neuron closed loop.

**B. Open-loop characterization (real data, feedback_off):** sweep the load amplitude. Record
joint displacement, sensory rate per cell and mapped-motor spikes (spikes occur but are not
applied). Pick the smallest load that crosses the sweep's threshold. This checks that the
body can produce the drive the network needs.

**C. Physical-feedback acceptance (real data):** for the chosen load, run the three
conditions. Pass if all hold:
1. feedback_on has mapped-motor spikes and non-neutral applied commands;
2. sensory_clamp is identical to feedback_off (sensory input alone changes nothing physical);
3. `max |q_on − q_off|` exceeds a threshold the owner sets (for example 0.01 rad, far above
   the 1e-9 Windows/Docker tolerance);
4. causality: the first trajectory difference comes after the first applied non-neutral
   command, which comes after the first mapped-motor spike plus the 10 ms decoder window;
5. the effect is present for every seed in 42–46;
6. no safety abort, no MuJoCo warning, finite state, clock drift within tolerance;
7. Windows and Docker runs reproduce exactly (`--compare`).

**D. Dose response (report, not a gate):** effect size against load amplitude; flexor and
extensor spike counts; motor latency compared with the sweep's latency.

## Decisions needed from the owner

1. Is a **sustained external load** an acceptable protocol for the first physical-feedback
   test, instead of perturb-and-release?
2. Is a **flexor-only** response acceptable as the first criterion, given that the
   extensors are inhibited under the current model?
3. What minimum effect size counts as a pass (proposed 0.01 rad)?
4. Keep the decoder unchanged (population mean over 5 flexors, `rmax` 100 Hz) for v0.8? The
   proposal keeps it and only records how far it saturates.
5. If option (a) fails: is a v2 encoder profile with a higher maximum rate (about 200 Hz)
   acceptable?

Contact/load sensing (owner's v0.8 idea) stays a later step. It needs a
literature-supported sensory population, which has not been selected.
